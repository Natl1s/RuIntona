# План улучшения проекта Dusha до уровня начинающего датасайнтиста

## Текущее состояние проекта

Проект已完成: пайплайн обработки данных, 16+ моделей (текст/аудио/мульти-
модальные), 3 ноутбука анализа данных, базовая документация.

**Что уже есть хорошо:**
- Рабочий пайплайн обработки данных (Dawid-Skene агрегация)
- Множество моделей от бейзлайнов до трансформеров
- Конфигурация через config_utils.py
- Jupyter ноутбуки для анализа данных
- Базовая документация (README, отчёты)

**Чего не хватает для уровня начинающего датасайнтиста:**
- Тесты, воспроизводимость, автоматизация, структура результатов

## Фаза 2: Тестирование (приоритет: высокий)

### 2.1 Unit-тесты утилит
- **Зачем**: `config_utils.py`, `lmdb_utils.py`, `metrics.py`, `text_utils.py` не имеют тестов — баги находятся только при запуске экспериментов
- **Что сделать**:
  - Создать `tests/` директорию в корне проекта
  - Написать тесты для:
    - `config_utils.py`: проверка загрузки конфистов, значений EMO2LABEL
    - `lmdb_utils.py`: парсинг меток, чтение LMDB (на мок-данных)
    - `metrics.py`: проверка weighted_accuracy, classification metrics
    - `text_utils.py`: preprocess_text, load_texts_from_manifest
    - `model_io.py`: save/load цикл для sklearn и PyTorch
  - Использовать pytest + fixtures

### 2.2 Smoke-тесты моделей
- **Зачем**: Убедиться что каждая модель может обучиться на маленьком батче и сделать предсказание
- **Что сделать**:
  - Для каждой модели добавить `--mode smoke` который запускает 1-2 эпохи на 100 сэмплах
  - Проверять что loss убывает и метрики в разумных пределах
  - Автоматизировать через pytest parametrize

### 2.3 Интеграционные тесты данных
- **Зачем**: Убедиться что данные корректно загружаются из LMDB/JSONL
- **Что сделать**:
  - Тесты загрузки JSONL с проверкой схемы (наличие hash_id, emotion, speaker_text)
  - Тесты загрузки LMDB с проверкой типов данных
  - Тест балансировки классов в `build_balanced_aggregated_jsonl.py`

## Фаза 4: Улучшение анализа данных (приоритет: средний)

### 4.1 Расширение EDA ноутбуков
- **Зачем**: Текущие ноутбуки покрывают базовый анализ, но не хватает:
- **Что добавить**:
  - **Длина аудио по классам**: boxplot + violin plot с статистическим тестом (Mann-Whitney)
  - **Корреляция текста и аудио**: длина текста vs длительность аудио
  - **Распределение спикеров по классам**: есть ли bias в данных?
  - **Качество транскрипций**: сравнение speaker_text vs transcription
  - **Vocabulary overlap**: насколько словари эмоций пересекаются?

### 4.2 Анализ ошибок моделей
- **Зачем**: Понять какие сэмплы модели путают и почему
- **Что сделать**:
  - Ноутбук `error_analysis.ipynb`:
    - Confusion matrices для каждой модели
    - Примеры ошибочных предсказаний с текстом и аудио
    - Анализ по спикерам: какие спикеры часто неправильно классифицируются?
    - Анализ по длине: коррелирует ли длина аудио с точностью?

### 4.3 Сводная таблица результатов
- **Зачем**: Сейчас результаты разбросаны по JSON-файлам — сложно сравнить модели
- **Что сделать**:
  - Скрипт `collect_results.py` который собирает все `metrics.json` в единый DataFrame
  - Визуализация: bar chart сравнения всех моделей по accuracy, F1, precision, recall
  - Таблица в Markdown/LaTeX для отчёта
