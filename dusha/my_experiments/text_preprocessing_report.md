## 1) Общий базовый этап для моделей из `text_models`: загрузка текста из LMDB

Все 4 модели используют `load_texts_from_lmdb(...)` из `lmdb_utils.py`. Поэтому до «модельной» предобработки всегда выполняется общий слой:

1. Открывается LMDB в read-only.
2. По каждому payload ищется текст в ключах по приоритету:
   - `speaker_text`, затем `text`, затем `transcript`, затем `utterance`.
3. Текст приводится к строке: `text = str(text)`.
4. Вызывается `preprocess_fn` конкретной модели (если передан).
5. После этого делается `strip()`; пустые строки отбрасываются.
6. Метка эмоции читается из `y` / `label` / `emotion` и нормализуется к одной из:
   - `angry`, `sad`, `neutral`, `positive`.

**Важно:** если ни один текстовый ключ не найден, бросается ошибка.  
То есть «тихого» пропуска без текста нет — это строгая валидация структуры данных.

## 2) Предобработка в каждой модели из `text_models`

## 2.1 `baseline/TF-IDF_LogReg.py`

### Этапы предобработки
1. **Типовая проверка**: если не `str` → вернуть пустую строку.
2. **Lowercase**: `text.lower()`.
3. **Нормализация пробелов**: `re.sub(r'\s+', ' ', text)`.
4. **Обрезка краев**: `strip()`.
5. Пустые тексты после обработки удаляются на уровне `load_texts_from_lmdb`.

### Превращение текста в признаки
1. `TfidfVectorizer` обучается на train-текстах:
   - `ngram_range=(1, 2)` (униграммы + биграммы),
   - `max_features=10000`,
   - `min_df=2`,
   - `max_df=0.8`,
   - `sublinear_tf=True`.
2. Train: `fit_transform`, Test: `transform`.

### Что это значит по сути
- Нормализация **минимальная** (без лемматизации, без удаления пунктуации вручную).
- Основной вклад в «очистку» вносит TF-IDF-фильтрация редких/слишком частых n-грамм.

---

## 2.2 `baseline/Embeddings_LogReg.py`

### Этапы предобработки
Текстовая предобработка такая же, как в TF-IDF-модели:
1. не-строка → `""`,
2. lowercase,
3. схлопывание пробелов,
4. `strip()`,
5. удаление пустых текстов в загрузчике LMDB.

### Превращение текста в признаки
1. Текст делится по пробелам: `text.split()`.
2. Для каждого слова берется FastText-вектор (`fasttext_model.wv[word]`).
3. Вектор текста = **среднее** всех векторов слов.
4. Если слов нет/векторов не получено → нулевой вектор.
5. После получения матрицы признаков применяется `StandardScaler`:
   - train: `fit_transform`,
   - test: `transform`.

### Особенность
- За OOV отвечает FastText (через subword n-граммы), но лингвистическая очистка текста в скрипте по-прежнему базовая.

## 2.3 `BiLSTM/BiLSTM.py`

### Этапы предобработки
1. не-строка → `""`,
2. lowercase,
3. схлопывание пробелов,
4. `strip()`,
5. удаление пустых текстов в LMDB-загрузчике.

### Этапы подготовки текста для нейросети
1. **Split train/val**: `train_test_split(..., stratify=y_train_raw)`.
2. **Словарь строится только по train_texts**:
   - токенизация: `text.split()`,
   - частоты токенов через `Counter`,
   - спецтокены: `<pad>` (0), `<unk>` (1),
   - фильтры: `min_freq`, `max_vocab_size`.
3. **Embedding matrix**:
   - для каждого токена словаря берется FastText-вектор,
   - PAD оставляется нулевым.
4. **Кодирование последовательностей**:
   - токены → индексы (неизвестные в `<unk>`),
   - усечение до `max_len`,
   - паддинг до `max_len`,
   - длина `length = max(1, len(ids))` для устойчивой упаковки.
5. `TextSequenceDataset` сохраняет:
   - `input_ids`,
   - `lengths`,
   - `labels` (через маппинг эмоций).
6. В модели используется `pack_padded_sequence`/`pad_packed_sequence`.

### Что важно
- Здесь уже есть полноценный этап **дискретной токенизации и словаря**, чего нет в TF-IDF/Embeddings-LogReg.
- Нормализация текста при этом все еще простая (без лемматизации).

---

## 2.4 `transformers/RuBERT.py`

### Этапы предобработки
1. не-строка → `""`,
2. `strip()`,
3. схлопывание пробелов.

**Отличие от предыдущих:** явного `lowercase` нет.  
Это логично для `DeepPavlov/rubert-base-cased`: регистр сохраняется.

### Этапы подготовки для трансформера
1. **Split train/val**: стратифицированный `train_test_split`.
2. Загрузка `AutoTokenizer.from_pretrained(backbone_name)`.
3. Токенизация батчем в `TransformerEmotionDataset`:
   - `padding="max_length"`,
   - `truncation=True`,
   - `max_length=max_len`,
   - `return_tensors="pt"`.
4. На выходе формируются:
   - `input_ids`,
   - `attention_mask`,
   - целевые классы.

### Что важно
- Вся «умная» обработка текста (субтокены, нормализация под словарь модели) делегирована токенайзеру Hugging Face.
- Ручная очистка в коде минимальна и намеренно щадящая.

---

## 3) Сравнение предобработки между моделями

| Модель | Базовая очистка | Lowercase | Спец. лингвистика | Признаки/токены |
|---|---|---:|---|---|
| TF-IDF_LogReg | trim + пробелы | Да | Нет | TF-IDF (1–2 граммы) |
| Embeddings_LogReg | trim + пробелы | Да | Нет | Средний FastText-вектор текста |
| BiLSTM | trim + пробелы | Да | Нет | Словарь + индексы + pad/truncate + FastText matrix |
| RuBERT | trim + пробелы | Нет | Нет (ручной) | AutoTokenizer: subword + attention_mask |

## 4) Подробно по `data_analise/text_analise.py`

Этот скрипт **не обучает классификатор**, а делает аналитическую обработку текста (важные слова, биграммы, графики).

## 4.1 Загрузка и первичная фильтрация
1. Читает JSONL построчно.
2. Берет:
   - `speaker_text` как текст,
   - `emotion` как метку.
3. Пропускает:
   - не-строковые тексты,
   - пустые строки,
   - битые JSON-строки,
   - строки без нужных ключей.

## 4.2 Лингвистическая предобработка (ядро скрипта)

Используются:
- расширенный `RUSSIAN_STOPWORDS`,
- маскирование командных интентов токеном `<COMMAND>`,
- (опционально) лемматизация через `pymorphy3`.

### Подэтапы `preprocess_text(text, use_lemmatization=True)`
1. lowercase;
2. нормализация пробелов;
3. `strip`;
4. **маскирование командных фраз** (`mask_command_phrases`, 1-й проход):
   - фиксированные фразы из `COMMAND_PHRASES`,
   - шаблон «числительное + серия/сезон»,
   - схлопывание повторов `<COMMAND>`.
5. **лемматизация** (если доступен pymorphy3):
   - каждое слово → normal form,
   - токены вида `<...>` не лемматизируются.
6. **маскирование после лемматизации** (2-й проход):
   - шаблон «командный глагол + объект» по леммам.

Итог: скрипт снижает влияние «командных» реплик и выделяет эмоциональную лексику.

## 4.3 Аналитические этапы после предобработки

### A) `analyze_tfidf_important_words`
1. Препроцессит все тексты с лемматизацией.
2. Строит **word-level TF-IDF**:
   - `ngram_range=(1,3)`,
   - `max_features=10000`,
   - `min_df=2`, `max_df=0.7`,
   - `sublinear_tf=True`,
   - стоп-слова удаляются.
3. Строит **char-level TF-IDF**:
   - `analyzer='char_wb'`,
   - n-граммы 3–5 символов,
   - `max_features=5000`, `min_df=2`, `max_df=0.7`.
4. Для каждой эмоции считает средний TF-IDF-вес и выводит топ слов/паттернов.

### B) `analyze_bigrams`
1. Опять препроцесс с лемматизацией.
2. `CountVectorizer` по биграммам:
   - `ngram_range=(2,2)`,
   - `min_df=2`, `max_df=0.5`,
   - стоп-слова удаляются,
   - `token_pattern` ограничивает токены словами из ≥2 букв.
3. Для каждой эмоции суммирует частоты и выводит топ-биграммы.

### C) Дополнительные этапы
1. Базовая статистика по длинам текстов (слова/символы) и примеры.
2. Сравнение словарей между эмоциями.
3. Визуализация:
   - топ-слова,
   - топ-биграммы,
   - wordcloud (если установлен `wordcloud`).

---

## 5) Ключевые выводы

1. В `text_models` предобработка в основном **минималистичная** (чистка пробелов, иногда lowercase), без лемматизации и без маскировки интентов.
2. Самая «глубокая» текстовая очистка реализована не в моделях, а в `text_analise.py`:
   - маскирование командных фраз,
   - двухпроходная логика до/после лемматизации,
   - расширенный список стоп-слов.
3. `RuBERT.py` намеренно не приводит к lowercase, что согласуется с cased-backbone.
4. `BiLSTM.py` добавляет важный инженерный слой подготовки последовательностей:
   - словарь train-only,
   - pad/unk/truncate,
   - явная длина последовательности для packed LSTM.
